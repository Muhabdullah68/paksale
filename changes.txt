================================================================================
  CRITICAL ISSUES (Severity = BLOCKER)
================================================================================

# C1 - MISSING MATERIAL ANCESTOR
   Severity : RED / BLOCKER
   Screenshot : Screenshot 4 (Home page)
   Root Cause : RangeSlider in _LeftSidebar requires a Material widget ancestor.
                Flutter renders a giant yellow/red error box that breaks the
                entire left sidebar + overlays page content. Price filter
                is unusable.
   Visual Impact : Full sidebar rendered as error banner, page content broken.

# C2 - MIDDLE-ONLY SCROLLING (Nested ScrollViews)
   Severity : RED / BLOCKER
   Screenshot : All 4 screenshots
   Root Cause : WebPage.build() uses Column -> Expanded -> content -> WebFooter.
                Expanded forces content into a fixed height box, so only the
                middle band scrolls via internal SingleChildScrollViews. Header
                stays glued to top, footer glued to viewport bottom. User
                experiences "stuck" middle scroll instead of natural document
                scroll.
   Visual Impact : Whole page feels "broken" like an iframe instead of a website.

# C3 - WIDGET OVERLAPPING / Z-INDEX STACKING
   Severity : RED / BLOCKER
   Screenshot : Screenshots 1, 2, 3
   Root Cause : 2 simultaneous causes:
                (a) The Categories mega-menu overlay (Positioned in Stack)
                    does NOT close on tab navigation -> when user clicks
                    Account/Saved, mega-menu stays in DOM partially covering
                    content.
                (b) AccountScreen/FavoritesScreen with webEmbedded=true include
                    their own SubTab bar (My Ads/Favorites/Settings) which stack
                    on top of the categories grid because IndexedStack doesn't
                    clip/sandbox children properly and all pages share the same
                    viewport layer - the mobile layout grids bleed through.
   Visual Impact : Screenshot 2 shows 4 layers visible at once:
                   SubTabs bar -> CTA banner -> Filter pills -> Category tile
                   grid - all overlapping.

# C4 - BOTTOM OVERFLOW (2.0px hazard bar)
   Severity : RED / BLOCKER
   Screenshot : Screenshot 3 (Favorites page)
   Root Cause : SocialMediaSection at the bottom of Favorites/Account content
                has fixed height that exceeds the Expanded content area.
                Combined with the Footer pushed by WebPage Column, there's a
                render overflow - Flutter shows the yellow/black warning
                stripes. Also affects Home Page when sidebar RangeSlider
                causes height overflow.
   Visual Impact : Professional-looking site ruined with "safety tape" visual.

================================================================================
  HIGH SEVERITY ISSUES (Design / UX)
================================================================================

# H1 - Expanded in WebPage forces footer as pseudo-fixed
   Severity : YELLOW / HIGH
   Location : web_shell.dart line 78
   Problem  : Footer sits at viewport bottom regardless of content. Expected
              behavior: Footer should be END OF DOCUMENT, not viewport bottom.
              User explicitly stated: "the buttom is not fixed" - current
              layout contradicts this.

# H2 - Mega-menu hover leaks across tabs
   Severity : YELLOW / HIGH
   Location : web_shell.dart lines 618-623
   Problem  : onEnter opens menu BUT no onExit handler to close menu when mouse
              leaves trigger. When user navigates to Account tab via header
              link BEFORE menu closes, menu remains open on next page.

# H3 - No Material ancestor around sidebar content
   Severity : YELLOW / HIGH
   Location : web_home.dart line 686
   Problem  : _LeftSidebar starts with SingleChildScrollView -> Column. No
              Material wrapper above RangeSlider/InkWells. Ink splashes fail,
              RangeSlider fails, widgets render without material ripples.
              This is direct cause of C1.

# H4 - IndexedStack children may contain their own Scaffolds/AppBars
   Severity : YELLOW / HIGH
   Location : home_screen.dart lines 219-223
   Problem  : CategoriesScreen, FavoritesScreen, AccountScreen with
              webEmbedded: true - if they still include their own AppBar/
              Scaffold body padding, they'll duplicate the header space (adding
              extra 56-80px top padding that WebPage header already used). This
              is the most likely cause of the overlapping SubTabs bar being
              pushed down into Category grid.

================================================================================
  MEDIUM / POLISH ISSUES
================================================================================

# M1 - Center column still uses BouncingScrollPhysics (mobile-only) on web
   Severity : BLUE / MEDIUM
   Location : web_home.dart line 108
   Problem  : Desktop marketplaces use ClampingScrollPhysics for professional
              feel. The whole point of the _WebScrollBehavior was to enforce
              this globally, but widget-level physics: parameters override it.

# M2 - Left sidebar uses BouncingScrollPhysics
   Severity : BLUE / MEDIUM
   Location : web_home.dart line 688
   Problem  : Same as M1 - inconsistent with web experience.

# M3 - WebPage ConstrainedBox nested in Expanded -> layout is fragile
   Severity : BLUE / MEDIUM
   Location : web_shell.dart lines 78-100
   Problem  : Using Expanded child with Column -> Expanded means any content
              exceeding viewport height triggers overflow yellow/black, since
              Expanded child has unbounded height only when Column is inside
              SingleChildScrollView (which it ISN'T in current WebPage).
